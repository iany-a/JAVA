Interface vs Abstract classes

runtime polymorphism overriding was done with virtual methods in C++

In JAVA all methods are virtual, so we do not use the "virtual" keyword (it's implicit)

Pure virtual method example:
_void move() = 0;_

Both interfaces and abstract classes can have pure virtual methods.
Seminar convention: **abstract = pure virtual**

Abstract classes can not be instanciated 
e.g.: AbstractClass a = new AbstractClass can not work

Interfaces - allways ends with "able" as it names an action that the 
interface is able to complete
_public interface Movable;_ Note: NO curly brackets for functions in interfaces.

Interface gets IMPLEMENTED by an abstract class. (or regular class, depending on scope)
non-interfaces (classes either abstract or regular) get EXTENDED by other classes.

NOTE: In JAVA, ONE class can ONLY inherit ONE class.
However, ONE class can implement MULTIPLE interfaces

implements Cloneable needs to be added if scope is to override clone() method.
